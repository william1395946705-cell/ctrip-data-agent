# Ctrip Silent Collector（授权测试版）

这是一个 Manifest V3 技术验证扩展，仅用于本人或明确授权的测试酒店账号。它只匹配 `https://ebooking.ctrip.com/*`，在当前已登录页面的 MAIN world 中发起 6 个已审核的同源只读查询，不依赖 Python CLI。

## 安装

0.3.1 增加“本地数据表 / 导出CSV”。每行保留一次采集，列出北京时间、UTC时间、统计窗口、全部核心指标和异常/身份状态。表格读取现有 history 缓存（默认最近20次、上限100次，所有门店合计），不自动增加保留上限。请定期导出备份。CSV可由Excel/WPS打开，ID和排名加文本前缀防止误转日期，部分软件显示单引号。数据不写回安装目录、不上传；下载位置由浏览器控制。详见随包的 INSTALL.txt（中文说明，英文文件名避免跨系统解压乱码）。

1. 在仓库根目录执行 `cd extension && npm run package`。
2. Chrome 打开 `chrome://extensions` 并开启“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择 `dist/ctrip-silent-collector/`。
4. 打开或手工刷新一个已登录的 eBooking 页面，等待页面稳定。
5. 0.3.0 默认在页面稳定后自动采集；无需点击按钮。扩展图标可查看结果、暂停自动采集或手动再采集。

也可以解压 `dist/ctrip-silent-collector.zip` 后加载解压目录。

## 行为边界

- 不导航、不点击、不输入、不刷新、不调用 `bringToFront()`，不修改页面表单。
- 不读取 Cookie、localStorage、Chrome Profile 或认证 header/token；`fetch(credentials: "include")` 仅让浏览器为同源请求自动携带当前会话。
- 不处理验证码、不绕过登录或风控，不退出登录，不清理网页 Cookie/cache。
- 只调用 4 个经营报告查询、1 个近 7 天 ROAS 查询和 1 个违约列表查询。
- 请求日期在运行时生成：经营报告使用昨日，ROAS 使用截至昨日的闭区间近 7 天。
- 请求前后严格比较 `location.href`；URL 变化时丢弃本次业务结果。
- 当前内置地图为 `controlled_test`，模块仍标记 `discovered`。0.3.0 授权本地测试允许打开/刷新后自动执行相同 6 个只读查询，不将地图提升为 verified。
- 每日本地日期完整快照一次；失败后等下次正常打开/刷新重试，默认间隔 30 分钟、每天最多 3 次，无定时网络轮询。策略来自 `automaticPolicy`（enabled/cooldownMinutes/maxAttemptsPerDay），默认值和上下限见 src/automatic.js。弹窗可暂停。手动按钮可绕过自动限额。
- 待人工复核的完整快照也会停止当天重复请求，但不写“身份验证成功”记录。频率按页面名称分组（无名称才用页面 ID）；同名不同酒店可能共用每日额度，不适合多酒店生产部署。结果附带请求实际使用的经营日期、ROAS 日期范围和本机时区。
- 结果和安全诊断只保存到 `chrome.storage.local`，不上传服务器。

## 当前范围限制

- 本轮不调用 30 天 ROAS。当 7 天 ROAS 为 0 或明确无数据时，扩展会标记金字塔模块不完整，绝不会把加载/请求失败误判成未投流。
- 违约接口仅在当前授权酒店“无违约”样本上验证；有违约正样本尚未验证。
- 这是授权浏览器 POC 包，不是 Chrome 商店或生产发布版本。
- 当前酒店 ID 可能为空；flow 行顺序沿用授权酒店已观察顺序，尚不支持跨酒店归属保证。测试期间不要切换酒店。
- 0.2.3 起，采集前后会重新读取当前页面酒店身份；名称或可见 ID 变化即整次结果失败。流量接口返回的本店 ID 会写入本地结果：若页面可见 ID，则必须精确匹配；若页面未暴露 ID，只能按已审核行序归属，并明确标记为 `manual_check_required`。
- 无页面可见 ID 时，结果不会被记为成功冷却，也不会提供可持久化的人工确认按钮；这是为了避免同名门店之间无法证明当前页面身份时发生错误绑定。授权测试人员仍可人工对照页面字段，但该证据不提升为自动身份验证。
- 普通 Chrome 多页面与连续六轮（含手工刷新）已有人工成功反馈，详情及证据限制见 `docs/HANDOFF.md`（仓库文件，不在 ZIP 内）。
- 更新源码后需在扩展管理页点击重新加载，并确认弹窗版本；仅刷新携程页面不会重新加载扩展后台代码。不要通过清理 Cookie 或重新登录解决旧版本问题。
